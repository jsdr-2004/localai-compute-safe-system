# Off-By-One Loop Bug Example in Python
=====================================================

An off-by-one loop bug occurs when the loop condition is incorrect, causing it to execute one more time than intended.

### The Bug:

```python
fruits = ['apple', 'banana', 'cherry']
for i in range(len(fruits)):
    print(f"Index {i}: {fruits[i]}")
```

In this example, the loop will output:

```
Index 0: apple
Index 1: banana
Index 2: cherry
Index 3: None (because list indices start at 0)
```

As you can see, the loop has one too many iterations.

### Fixing the Bug:

To fix this bug, we need to adjust the loop condition so that it doesn't execute when `i` is equal to the length of the list. We can do this by using a range that stops one iteration before the expected end index.

```python
fruits = ['apple', 'banana', 'cherry']
for i in range(len(fruits) - 1):
    print(f"Index {i}: {fruits[i]}")
```

In this corrected version, the loop will only execute for indices 0 and 1:

```
Index 0: apple
Index 1: banana
```

By subtracting 1 from `len(fruits)`, we ensure that the loop doesn't try to access an index that's out of bounds.

### Alternative Solution:

Alternatively, you can use slicing to iterate over the list without having to worry about off-by-one bugs. Here's how you can do it:

```python
fruits = ['apple', 'banana', 'cherry']
for i, fruit in enumerate(fruits):
    print(f"Index {i}: {fruit}")
```

In this version, `enumerate` returns both the index and value of each item in the list, eliminating the need for an off-by-one fix.
