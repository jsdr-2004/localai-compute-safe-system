When using `docker ps`, if you encounter a "permission denied" error, it typically indicates that the Docker daemon is not running or there's an issue with its configuration. Here are some common reasons and troubleshooting steps to diagnose and resolve this issue:

### 1. Docker Daemon Not Running
**Cause:** The Docker service might be stopped.
**Solution:**
- Start the Docker service:
```bash
sudo systemctl start docker
```
- Enable the Docker service so it starts automatically on boot (Linux only):
```bash
sudo systemctl enable docker
```

### 2. SELinux or AppArmor Running in Enforcing Mode
**Cause:** Security modules like SELinux or AppArmor might be enforcing and blocking Docker.
**Solution:**
- Temporarily disable SELinux/AppArmor:
For SELinux, you can use the following command to temporarily drop into permissive mode (this is not recommended for production):
```bash
sudo setenforce 0
```
For AppArmor, you can remove or comment out the Docker configuration in `/etc/apparmor.d/` if it exists.

- Alternatively, configure SELinux/AppArmor to allow Docker:
For SELinux, you might need to adjust security contexts. You can use `chcon -Rv --reference=/var/lib/docker /path/to/directory` to copy context from a directory that is already accessible by Docker.
For AppArmor, you may need to modify the Docker configuration files in `/etc/apparmor.d/`.

### 3. Incorrect Docker Configuration
**Cause:** The Docker daemon might be misconfigured or not correctly set up with your user permissions.
**Solution:**
- Check if Docker is running as a non-root user (recommended for security reasons). If it's not, you can change the ownership of the Docker socket:
```bash
sudo chown $(id -u):$(id -g) /var/run/docker.sock
```
- Verify that your user has the necessary permissions to start and manage Docker services.

### 4. Incorrect User Permissions
**Cause:** Your current user might not have the required permissions to interact with Docker.
**Solution:**
- Ensure you are logged in as a user who is part of the `docker` group:
```bash
sudo usermod -aG docker $USER
```
Log out and log back in, or run:
```bash
newgrp docker
```
