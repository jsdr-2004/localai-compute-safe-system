 The error "permission denied" when running `docker ps` typically occurs due to one or more of the following reasons:

1. Incorrect user permissions: By default, Docker commands are run as the root user. If you're not logged in as root, you'll encounter a permission denied error. To resolve this issue, either log in as the root user or use `sudo` to execute the command.

2. Improperly configured Docker group: In some cases, users are added to the "docker" group which allows them to run docker commands without sudo. If you've created a new user and haven't added them to the "dockers" group, this can lead to permission denied errors. To resolve this issue, add your user to the "docker" group using the command:

   ```
   sudo usermod -aG docker $USER
   ```
   After adding the user, log out and log back in for the changes to take effect.

3. Incorrect Docker configuration: If you've recently installed or upgraded Docker, it's possible that the configuration file `/etc/docker/daemon.json` might have incorrect settings causing permission issues. To troubleshoot this issue, check if the file exists and verify that its permissions are set correctly (755 or 644).

   ```
   ls -l /etc/docker/daemon.json
   ```

4. Incorrect file ownership: If you've manually created Docker files, make sure they have the correct owner and group. Run the following command to check the owner of the Docker socket file:

   ```
   ls -l /var/run/docker.sock
   ```

   If necessary, change the ownership using the `chown` command:

   ```
   sudo chown yourusername:dockers /var/run/docker.sock
   ```

5. Incorrect permissions on Docker files and directories: Ensure that all Docker related files and directories have the correct permissions (755 or 644). To check the permission of the `/var/lib/docker` directory, run:

   ```
   ls -ld /var/lib/docker
   ```
