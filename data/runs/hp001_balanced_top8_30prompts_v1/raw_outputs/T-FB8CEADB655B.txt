The `rm -rf` command, when used on a remote file system, is generally considered safe and does not block in most Unix-like systems due to several reasons:

1. **Remote File Systems**: Many remote file systems, such as FTP (File Transfer Protocol), SFTP (Secure File Transfer Protocol) or SSH (Secure Shell), do not block commands like `rm -rf` until they are actually executed. They allow the command to be sent and received without immediate blocking.

2. **Background Execution**: Commands can often be executed in the background, which means that while one process is running with an executable command, it doesn't prevent other processes from continuing to run or being executed immediately.

3. **Shell Scripts**: Shell scripts are often used for automation tasks. These scripts can include commands like `rm -rf` and may not block until all the script has been run.

4. **Remote File System Permissions**: If you're running on a remote system, you might be able to access file permissions that allow the command to proceed even if it's blocked in your local shell session.
