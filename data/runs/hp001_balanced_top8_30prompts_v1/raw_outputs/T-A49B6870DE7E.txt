**Permission Denied Error in Docker `ps` Command**

The "permission denied" error when running the Docker `ps` command can be caused by several factors. Here are some common reasons and solutions:

### 1. Insufficient Permissions

*   **Solution:** Ensure that you have the necessary permissions to access the Docker daemon. Run the following command as root or with elevated privileges:
    ```bash
sudo docker ps
```
    Alternatively, you can run `docker ps` without sudo if your user has been granted the necessary permissions.

### 2. Running Docker Without Sudo

*   **Solution:** If you're running Docker without sudo, ensure that your user account has the necessary permissions to access the Docker daemon. You can check the permissions by running:
    ```bash
getfacl -R /var/run/docker.sock
```
    If your user doesn't have write access to `/var/run/docker.sock`, run the following command as root or with elevated privileges:
    ```bash
sudo setfacl -R u:your_username:rwx /var/run/docker.sock
```

### 3. Docker Daemon Not Running

*   **Solution:** Ensure that the Docker daemon is running and listening on the default port (2375). You can check the status of the Docker daemon by running:
    ```bash
sudo systemctl status docker
```
    If the Docker daemon is not running, start it using:
    ```bash
sudo systemctl start docker
```

### 4. Docker Configuration Issues

*   **Solution:** Check your Docker configuration files (e.g., `/etc/docker/daemon.json`) for any permissions-related issues.

### 5. Running Docker with a Non-Root User

*   **Solution:** If you're running Docker with a non-root user, ensure that the user has been granted the necessary permissions to access the Docker daemon. You can check the permissions by running:
    ```bash
getfacl -R /var/run/docker.sock
```
    If your user doesn't have write access to `/var/run/docker.sock`, run the following command as root or with elevated privileges:
    ```bash
sudo setfacl -R u:your_username:rwx /var/run/docker.sock
```

### 6. Docker Compose Issues

*   **Solution:** If you're using Docker Compose, ensure that your `docker-compose.yml` file is correctly configured and that the necessary permissions are in place.
