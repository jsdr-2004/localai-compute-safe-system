 The error "permission denied" when running `docker ps` can occur due to several reasons:

1. **Incorrect User:** By default, Docker runs with root privileges, and regular users may not have access unless they are added to the `docker` group. If you're not a sudo user or part of the `docker` group, you might encounter this error. You can verify your group membership by running:

   ```
   cat /etc/group | grep docker
   ```

   To add a user to the `docker` group, use the following command:

   ```
   sudo usermod -aG docker $USER
   ```

   After running this command, you need to log out and log back in so that the group membership is updated. Alternatively, you can run Docker commands as root by using `sudo`:

   ```
   sudo docker ps
   ```

2. **Incorrect Executable Permissions:** Ensure that the Docker executable has the correct permissions. You can check and adjust them with the following commands:

   ```
   ls -l /usr/bin/docker
   chmod +x /usr/bin/docker
   ```

3. **Docker Service Not Running:** If Docker is not running, you won't be able to interact with it using the `docker ps` command. To check if Docker is running, use:

   ```
   systemctl status docker
   ```

   If it's not running, start it using:

   ```
   sudo systemctl start docker
   ```

   Or, to enable Docker to start automatically at boot, use:

   ```
   sudo systemctl enable docker
   ```

4. **Docker Daemon Configuration:** If none of the above solutions work, there might be a problem with your Docker daemon configuration. Check the logs for errors or issues:

   ```
   journalctl -u docker
   ```

   You may need to manually start the Docker daemon if it's not working correctly. For systems using systemd, you can do this with:

   ```
   sudo systemctl start docker
   ```
