When using `docker ps` and encountering a "permission denied" error, it typically indicates that the Docker daemon is not running with sufficient permissions or that you do not have the necessary privileges to access the container list. Here are some common reasons for this issue and how to resolve them:

### 1. Docker Daemon Not Running
**Issue:** The Docker daemon might be stopped.
**Solution:**
- Ensure that the Docker service is running by using:
```sh
sudo systemctl start docker
```
or if you're on a different system, use:
```sh
sudo service docker start
```
You can also check its status with:
```sh
sudo systemctl status docker
# or
sudo service docker status
```

### 2. Docker Daemon Running as Root
**Issue:** The Docker daemon is running as root and you are not a member of the `docker` group.
**Solution:**
- Add your user to the `docker` group:
```sh
sudo usermod -aG docker $USER
# Log out and log back in for this change to take effect, or run:
newgrp docker
```
- Alternatively, you can start Docker without root privileges by using a non-root user account.

### 3. SELinux or AppArmor Conflicts
**Issue:** SELinux/AppArmor policies might be blocking access.
**Solution:**
- For SELinux, ensure that the `docker` context is properly set:
```sh
sudo chcon -Rv --type=container_file /var/run/docker.sock
```
- For AppArmor, you may need to adjust your policy configuration.

### 4. Docker Daemon Not Running as a Non-root User
**Issue:** The Docker daemon might be running as root and not configured to use non-root users.
**Solution:**
- Ensure that the Docker service is set up to run as a non-root user:
```sh
sudo mkdir -p /var/run/docker
sudo chown $(id -u):$(id -g) /var/run/docker
```
- Configure your Docker daemon configuration file (`/etc/docker/daemon.json`) accordingly.

### 5. Firewall or Network Issues
**Issue:** Your network might be blocking the connection to the Docker socket.
**Solution:**
- Ensure that your firewall is not blocking connections to the Docker socket (usually `/var/run/docker.sock`).
```sh
sudo ufw allow 'Docker'
```
or for other firewalls:
```sh
sudo iptables -A
