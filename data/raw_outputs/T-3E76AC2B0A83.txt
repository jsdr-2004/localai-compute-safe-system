**Likely Cause:**

When a user runs `docker ps` and gets a "permission denied" error, it's often due to one of the following reasons:

1. **Insufficient Docker permissions**: The user may not have the necessary permissions to access Docker resources.
2. **Incorrect group membership**: The user might be part of a group that doesn't have Docker permissions.
3. **Docker socket ownership issues**: The Docker socket (usually `/var/run/docker.sock`) is owned by a different user or group, preventing the current user from accessing it.

**Safe Fix:**

To resolve this issue, you can try the following steps:

### 1. Check and adjust Docker permissions

Run the following command to check the Docker permissions:
```bash
getfacl -R /var/run/docker.sock
```
This will display the file system access control list (ACL) for the Docker socket.

If the user is not in the `docker` group, you can add them to it using the following command:
```bash
usermod -aG docker $USER
```
Replace `$USER` with the actual username of the user experiencing permission issues.

### 2. Change ownership of the Docker socket

If the user is already in the `docker` group but still experiences permission issues, you can try changing the ownership of the Docker socket:
```bash
sudo chown $USER:$USER /var/run/docker.sock
```
This will change the ownership of the Docker socket to the current user.

### 3. Run Docker as a non-root user

If none of the above steps work, you can try running Docker as a non-root user using the `--user` flag:
```bash
docker run --user $USER my-image
```
This will run the container in the context of the current user.

### 4. Check and adjust group membership

Run the following command to check the groups that the user is part of:
```bash
groups $USER
```
If the user is not part of a group with Docker permissions, you can add them to a suitable group using the `usermod` command:
```bash
usermod -aG docker mygroup
```
Replace `mygroup` with an existing group that has Docker permissions.

By following these steps, you should be able to resolve the "permission denied" error when running `docker ps`.
