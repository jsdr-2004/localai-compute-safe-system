 The error "permission denied" when running `docker ps` usually indicates that the Docker service is not running with sufficient permissions, or the user does not have the necessary privileges to interact with the Docker daemon. Here are some safe fixes:

1. Check if Docker is installed correctly and running:
   - Verify that Docker is installed by checking for the `docker` command in your system's path.
   - Ensure Docker is running with the following command: `sudo systemctl status docker` or `sudo service docker status`, depending on your Linux distribution. If it's not running, start it using `sudo systemctl start docker` or `sudo service docker start`.

2. Configure Docker to use the current user:
   - To allow regular users to run Docker commands without sudo, you can add the current user to the `docker` group. Run the following command: `sudo usermod -aG docker $USER` (replace $USER with your username).
   - After adding the user to the docker group, log out and log back in for the changes to take effect or you can use the following command to apply the changes immediately: `su - $USER`

3. If you are using a non-root user and still facing permission issues, you may need to use the `--user $(id -u)` flag when starting Docker. Edit the Docker daemon configuration file located at `/etc/docker/daemon.json` (or `/lib/systemd/system/docker.service.d/daemon.json` on systemd-based systems), and add the following content:
   ```
   {
       "user": "(your user ID)"
   }
   ```
   Replace (your user ID) with the numerical user ID associated with your username, which can be found using the command `id -u $USER`. Save the file and restart Docker to apply the changes.

4. If you still encounter issues after trying these solutions, consider setting up TLS authentication between the client and daemon for improved security:
   - Generate a new key pair for Docker by running `sudo docker secret create docker-key`
   - Configure the Docker daemon to use the new key pair in its configuration file (`/etc/docker/daemon.json` or `/lib/systemd/system/docker.service.d/daemon.json`) by adding:
     ```
     {
       "tls": true,
       "tlscacert": "/path/to/ca.pem",
       "tlscert": "/path/to/client.pem",
       "tlskey": "/path/to/private.key"
     }
     ```
   - Replace the paths with appropriate locations for your system.
   - Restart Docker to apply the changes.

5. Lastly, verify that the issue is resolved by running `docker ps` again without using sudo or any special flags.
