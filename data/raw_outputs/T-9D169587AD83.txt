When a user tries to run `docker ps` and receives a "permission denied" error, it typically means that the Docker daemon does not have the necessary permissions to access the container's logs or other system directories.

Here are some likely causes:

1. **Docker Daemon Not Running**: The most common reason is that the Docker daemon is not running at all. This can happen if you've recently stopped the service, or perhaps it failed to start correctly in the first place.
   
2. **SELinux/AppArmor/SeLinux Policies**: On some Linux distributions, SELinux, AppArmor, or SeLinux policies might be configured such that the Docker user (usually `docker`) does not have permission to access certain directories or files.

3. **Docker User Permissions Issue**: The Docker daemon runs as a different user (often `docker`), and there may be issues with file permissions for this specific user group or individual files within the `/var/lib/docker`.

Here is how you can safely troubleshoot and fix such an issue:

### Step 1: Verify Docker Daemon Is Running
First, ensure that the Docker daemon is running. You can use `systemctl` on systems using systemd (commonly used in Ubuntu/Debian):

```bash
sudo systemctl status docker
```

If it's not running, start it with:
```bash
sudo systemctl start docker
```
And then check its status again to ensure it started successfully:
```bash
sudo systemctl status docker
```

### Step 2: Check Permissions on Docker Logs Directory
Sometimes the issue is related to the permissions of the directory where logs are written (usually `/var/lib/docker/containers`). You can fix this by changing ownership:

```bash
sudo chown -R $(id -u):$(id -g) /var/lib/docker/
```

### Step 3: Verify Docker User Group Membership
Ensure that the Docker user (often `docker`) is a member of the group managing the log directory. You can add it like this:

```bash
sudo usermod -aG docker $(whoami)
```
After running this command, you will need to log out and back in for the changes to take effect.

### Step 4: Verify SELinux/AppArmor Policies (if applicable)
If SELinux or AppArmor policies are causing issues, you might need to adjust them. Here is a general approach:

For SELinux:
```bash
sudo setenforce 0  # To test if SELinux is the issue, temporarily disable it.
sudo semodule -e docker  # Disable specific module that Docker uses (depends on your setup)
```

For AppArmor:
```bash
sudo aa-disable /etc/apparmor.d/dockerd.conf
```
Adjust these settings according to your system configuration.

### Step 5: Restart Docker Daemon
After making changes, restart the Docker service to apply them:

```bash
sudo systemctl restart docker
```

If none of the above steps resolve the issue, you might need to consult specific documentation for your Linux distribution or use more detailed troubleshooting methods like checking logs (`/var/log/syslog` and `/var/log/docker.log`).
