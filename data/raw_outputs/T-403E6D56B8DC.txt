 The error "permission denied" when running `docker ps` usually indicates that the Docker daemon is running but the user does not have sufficient permissions to interact with it. Here are a few steps to troubleshoot and resolve this issue:

1. Check if Docker is installed correctly by running `docker --version`. If it's not installed, you need to install Docker first.

2. Verify that the Docker daemon is running using the command `sudo systemctl status docker`. If it's not running, start it with `sudo systemctl start docker` or enable and start it with `sudo systemctl enable --now docker`.

3. To allow a user to interact with Docker without using sudo, you can add the user to the `docker` group. First, find the username by running `whoami`, then use the following command:

   ```
   sudo usermod -aG docker $USER
   ```

4. After adding the user to the `docker` group, you may need to log out and log back in for the changes to take effect or run `newgrp docker`.

5. Finally, test if the issue is resolved by running `docker ps` again without sudo. If it still doesn't work, restart your terminal or run `source ~/.bashrc` to reload the shell configuration file.

6. If you are using a system that uses systemd instead of systemctl (like Arch Linux), use `sudo systemd-tmpfiles --create /etc/tmpfiles.d/docker.conf` to create a new configuration file and add the following line:

   ```
   d - /var/run/docker.sock - - - 0660 docker docker
   ```

   Then, restart Docker with `sudo systemctl restart docker`. This will set the correct permissions for the Docker socket file.
