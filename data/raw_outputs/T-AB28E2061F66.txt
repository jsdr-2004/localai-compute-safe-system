 The error "permission denied" when running `docker ps` usually indicates that the Docker daemon is running but the user doesn't have the necessary permissions to interact with it. Here are a few steps to help resolve this issue:

1. Check if Docker is installed correctly by running `docker --version`. If it's not installed, you can install Docker following the instructions for your specific operating system at https://docs.docker.com/get-docker/.

2. Verify that the Docker daemon is running with `sudo systemctl status docker` or `sudo service docker status` (depending on your Linux distribution). If it's not running, you can start it using `sudo systemctl start docker` or `sudo service docker start`.

3. To allow the user to interact with Docker without requiring sudo, add the current user to the `docker` group by executing:

   ```
   sudo usermod -aG docker $USER
   ```

4. After adding the user to the `docker` group, you may need to log out and log back in for the changes to take effect or use `newgrp docker` to immediately apply the changes:

   ```
   newgrp docker
   ```

5. Now, try running `docker ps` again without sudo. If everything is set up correctly, you should see a list of active Docker containers.
