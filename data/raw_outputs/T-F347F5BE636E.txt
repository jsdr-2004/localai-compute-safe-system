When running `docker ps`, you might encounter a "permission denied" error if your Docker daemon is not configured to allow listing of containers, or if your current user does not have sufficient permissions to access it.

### Likely Cause:
The most common reason for encountering a permission issue when trying to list Docker containers with `docker ps` is that the Docker service is running as a different user than the one you are currently logged in as. This can happen if Docker was installed system-wide (not using a container runtime like Podman or LXD) and configured to run under a non-root user.

### Safe Fix:
To resolve this issue, you should ensure that your current user has permission to interact with the Docker daemon. Here’s how you can do it:

1. **Check if Docker is Running as Root:**
   First, check whether Docker is running as root or another user. You can use `systemctl` (for systemd-based systems) or `service` (for older system services).

   ```sh
   systemctl status docker  # For systemd based systems
   service docker status     # For older system services
   ```

2. **Check Docker User:**
   If Docker is running as root, you can change its user to a non-root user with the appropriate permissions.

   ```sh
   sudo chown $(id -u):$(id -g) /var/run/docker.sock
   ```

3. **Verify Permissions:**
   Ensure that your current user has permission to access Docker’s socket file:

   ```sh
   ls -l /var/run/docker.sock
   ```

   It should show something like `srwxr-xr-x` for the permissions, indicating that all users can read and write (execute) it.

4. **Restart Docker Service:**
   After ensuring proper ownership and permissions, restart the Docker service to apply changes:

   ```sh
   sudo systemctl restart docker  # For systemd based systems
   sudo service docker restart     # For older system services
   ```

### Additional Considerations:
- If you are using a non-root user for Docker (e.g., `docker` or another specific user), ensure that this user has the necessary permissions to access and interact with Docker.
  
- **Security Note:** Running Docker as root is generally not recommended due to security concerns. It’s better to run Docker as a non-root user, which can be done by setting up Docker in a container runtime like Podman or LXD.

By following these steps, you should be able to resolve the "permission denied" error when trying to list Docker containers using `docker ps`.
