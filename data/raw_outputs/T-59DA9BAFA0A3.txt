When running `docker ps` and encountering a "permission denied" error, it typically indicates that Docker does not have sufficient permissions to list containers on your system. This can happen for several reasons:

1. **Docker is not installed with root privileges**: If Docker was installed without elevated privileges (e.g., using the default installation method which often installs Docker as a non-root user), running commands like `docker ps` might fail if you do not have appropriate permissions to access or list containers.

2. **SELinux/AppArmor policies**: On systems where SELinux or AppArmor is enabled, these security modules can sometimes block Docker from accessing container information due to misconfiguration or overly restrictive rules.

3. **User-specific issues**: Sometimes, the user running the command might not have the necessary permissions to access the Docker socket or directories used by Docker.

### Likely Cause
Given that you're seeing a "permission denied" error when trying to list containers with `docker ps`, it's most likely related to one of the first two points: Docker was installed without root privileges, and your user does not have permission to access the necessary files or sockets.

### Safe Fix

To resolve this issue safely, follow these steps:

1. **Check if Docker is installed as a non-root user**:
   - Run `docker info` to see where Docker is configured.
   - If Docker was installed without root privileges (e.g., using a non-root user), you will need to switch to the root user or use sudo.

2. **Switch to root user and run docker ps**:
   ```sh
   sudo docker ps
   ```
   This command should allow you to list your containers if Docker is correctly installed as a non-root service.

3. **Verify SELinux/AppArmor policies (if applicable)**:
   - If SELinux or AppArmor are enabled, they might be blocking access.
   - You can temporarily disable these security modules by running the following commands:
     ```sh
     sudo setenforce 0 # For SELinux
     sudo systemctl stop apparmor.service # For AppArmor
     ```
   - After testing with `docker ps`, you can re-enable them if necessary.

4. **Check Docker configuration**:
   - Ensure that Docker is configured to use the correct socket and directories.
   - You might need to adjust permissions or ownership of files used by Docker, such as `/var/run/docker.sock`.

5. **Reinstall Docker with root privileges (if needed)**:
   - If you have access to a machine where you can reinstall Docker, ensure it is installed as a non-root user and verify the installation.

### Conclusion
The "permission denied" error when running `docker ps` usually points towards insufficient permissions rather than a fundamental issue with Docker itself. By ensuring Docker has the necessary privileges or adjusting security policies, you should be able to resolve this issue safely.
