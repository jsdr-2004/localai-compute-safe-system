When a user encounters "permission denied" when trying to run `docker ps`, it typically indicates that the Docker service is running with restricted permissions, or there might be an issue with file system permissions affecting Docker's ability to access certain directories.

### Likely Causes

1. **Docker Service Running as Non-Root User**: If Docker is configured to run under a non-root user (like `nobody`), it may not have the necessary permissions to read files in locations where Docker expects them to be, such as `/var/run/docker.sock`.

2. **Incorrect SELinux or AppArmor Profile**: On systems with SELinux or AppArmor enabled, incorrect security policies might prevent Docker from accessing its required directories.

3. **Filesystem Permissions Issues**: There could be permission issues within the Docker data directory (usually located at `/var/lib/docker/` on Linux systems). If files in these directories are not readable by the user running Docker commands, it can result in a "permission denied" error.

### Safe Fix

To resolve this issue without making significant changes to system security settings, you should first ensure that the Docker service is configured correctly. Here’s how you can do it:

1. **Check if Docker is Running as Root**:
   - Check the current user and group of the Docker process using `systemctl show docker --property=SubProcessUser` (on systemd-based systems like Ubuntu, CentOS) or similar command for your system.
   
2. **Verify the Docker User and Group**: If Docker is running under a non-root user, ensure that this user has appropriate permissions to access the required directories.

3. **Grant Permissions on Docker Data Directory**:
   - Ensure that the user (typically `nobody` if it’s running as non-root) owns or has read permissions for `/var/run/docker.sock`.
   
4. **Restart Docker Service**: After making changes, restart the Docker service to apply them.

### Steps in Detail

1. **Check Current User**:
   ```sh
   systemctl show docker --property=SubProcessUser
   ```

2. **Grant Permissions on Data Directory**:
   - Change ownership of the directory if needed.
   ```sh
   sudo chown -R nobody:nogroup /var/lib/docker/
   ```
   - Or, grant read permissions to a user group that might be used by Docker (e.g., `docker`) and ensure this group is included in your system's default groups list.

3. **Restart Docker Service**:
   ```sh
   sudo systemctl restart docker
   ```

If the issue persists after these steps, it may be helpful to look into SELinux or AppArmor logs for more detailed errors:

- For SELinux: Check `/var/log/audit/audit.log` (or similar location depending on your SELinux version) and search for AVC messages related to Docker.
- For AppArmor: Look at the log files where AppArmor writes its audit information, usually located in `/var/log/apparmor/`.

By ensuring that the necessary directories are accessible and Docker is running with appropriate permissions, you should be able to resolve the "permission denied" issue when using `docker ps`.
