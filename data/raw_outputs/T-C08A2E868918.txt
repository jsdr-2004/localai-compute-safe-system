When a user runs `docker ps` and gets a permission denied error, it's usually due to one of the following reasons:

1. **Root or Superuser account**: The command is being run with elevated privileges as a root or superuser account. This means that Docker has access to sensitive permissions like `USER`, `ALL`, and `SYSTEM`.
2. **Incorrect Docker credentials**: The user trying to run the command may not have the correct Docker credentials (e.g., API token, username/password) set up.
3. **Docker version or version-specific issues**: If you're using an older version of Docker that doesn't support certain features, it might cause permission denied errors.

To fix this issue:

**1. Run as a non-root user**: Instead of running `docker ps` with elevated privileges, try running the command from a non-root user account. For example:
```bash
sudo docker ps
```
This will grant the current user the necessary permissions to run the command without elevating to root.

**2. Check Docker credentials**: Make sure you have the correct Docker API token or username/password set up in your Docker configuration file (e.g., `docker-compose.yml`, `docker-compose-security.yml`). If you're using environment variables, ensure they are properly configured.

You can add the following lines to your Docker configuration files:
```yaml
image: docker:latest

api:
  enabled: true
```
or
```yml
version: "3"

services:
  # ...
  default-registry:
    registry: <your_registry_url>
    password: $(docker secret -r <registry_name> --get-password <api_token>)
```
If you're using an insecure storage driver (e.g., `local`), update the credentials to use a secure method, such as:

```yaml
image: docker:latest

driver:
  enabled: true
```

**3. Check Docker version**: Ensure that your Docker installation is up-to-date and compatible with your version of Docker. Sometimes, older versions may not support certain features or have compatibility issues.

**4. Verify the Docker configuration file**: Double-check that your Docker configuration files are correctly configured to allow non-root users to run `docker ps`.

By attempting to run the command with elevated privileges as a non-root user and checking for correct Docker credentials, you should be able to resolve the permission denied error.
